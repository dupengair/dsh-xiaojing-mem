# 02 · 场景化机制讲解（dsh-fish-memory）

> 配套 [01_dsh-fish-memory机制分析.md](01_dsh-fish-memory机制分析.md)。01 按源码结构讲"是什么"，这篇按"一个日子怎么过"讲"为什么"。版本 v1.5.8，行号以 `lib/index.js` 为准。
>
> **最重要的澄清**：库里能看到的 JSON 日志（`traces`）**不是聊天记录，也不是记忆本体**，而是召回日志——"这一轮为了回答你，翻了哪些记忆、各打了多少分"的体检报告。很多困惑都源于把它当成了记忆本身。

---

## 场景一：同一个工作区里开了好几个会话

### 1.1 记忆库文件里有什么

`~/.dsh/fish-memory/ws_<工作区id>.json`（workspace 模式，v1.4.5 起；session 模式则是 `<会话id>.json`）。`storePath` 定义在 lib/index.js:294，库名在 lib/index.js:432。结构：

| 块 | 是什么 |
|---|---|
| `policy` | 打分参数（半衰期、权重、门槛…） |
| `memories` | **真正的记忆**，一条一条 |
| `traces` | 召回日志（每轮一次） |
| `deleted` | 删除墓碑，防"删掉的记忆被旧快照复活" |

一条 trace 逐字段翻译：

```jsonc
"at": 1794243685265          // 时间戳
"session": "session-11b7…"   // 哪个会话发起的这次回忆
"query": "是呀小鯨…"         // 拿去检索的句子（已剥掉宿主注入的杂音）
"gate": 1.17, "gateLimit": 0.8
// 门卫：这句话信息量 1.17 > 门槛 0.8 → 放行
// ("在吗""哈哈"这种话 gate 低于门槛 → 整轮不翻记忆，省力气)
"picked": ["mmw7h2zoo658"]   // 最终注入进脑子的记忆 id
"rows": [ … ]                // 全体候选成绩单（最多记前 24 名）
```

`rows` 每行一条候选：

- **C** 证据分：你的话和这条记忆撞上多少"稀有词"。0 = 一个词没撞上（`hard_gate`）；0.279 < 门槛 0.3 → `below_threshold`（差一点，没进来）。
- **P** 总分 = C ×（基础 + 鲜活 + 重要 + 情绪加成），**只排座次，不决定进门**。
- **status**：`assembled` = 已注入；本轮结束后再查一遍回复有没有真用上，用上升级 `consumed`——设置页"像是用上了"就是这么来的。

### 1.2 "同一句话重复多条 trace"之谜

不是记忆重复，是**日志重复**。先讲一个验证过的规律：**插件不需要用户说话才干活**——任何一轮（包括主动搭话轮）装配时都会拿"最近那句人话"去检索、记一条 trace。同一 query 反复出现，是机制本身，不是坏。在此之上才是两个技术成因：

1. 旧版 bug：同一次请求装配函数被调两遍，各记一条。v1.5.2 已修——同 query 且 <3000ms 直接覆盖（lib/index.js:4478-4500）；
2. 工作区模式多个会话轮流写各自的 trace，看起来像重复。

**`memories` 本体有去重+强化机制，不会重复。** 且 traces 只留最近 100 条、每条 rows 截 24 → 文件不会无限膨胀。

### 1.3 文件会无限增长吗

三道闸：`memories` 受每日写入配额（dailyQuota，默认 8，**限的是"每天记几条"不是库存总量**）；`traces` 只留最近 100 条——`if (data.traces.length > 100) data.traces = data.traces.slice(-100)`（lib/index.js:677，**标准 FIFO**，每次保存时挤掉最旧的）；每条 trace 的 rows 截 24。几百条记忆即稳态。

### 1.4 多会话并发写一个文件，怎么不打架

两个机制叠加：

1. **原子写**：`writeFileAtomicSync`（lib/atomic-file.mjs）——写临时文件→改名顶替，无中间态；写坏了自动备份（`backupCorruptStore`）。
2. **写前合并**：`saveStore`（lib/index.js:620）写前先把磁盘最新版读回来，按 id 合并（lib/store-merge.mjs）——B 会话刚记的不会被 A 手里的旧快照覆盖。这个 bug 真实发生过（"自动扩词等模型那几秒里新记忆丢了"）才补上。

所以不是排队顺序写，而是**每次写都先拉取最新再合并**——像 git rebase，不是 append。没有多个临时文件共存：每次写只有**一个**临时文件，改名顶替后立刻消失，磁盘上永远只有一个完整版本。举例：A1 落盘 → B 写时读到的已含 A1，合并后写 → A 写第二轮时读到的已含 A1+B1。**每一份落盘都把之前的全部吸收进去了**，不存在"A1、B1、A2、B2 等待合并"的局面。另有 `purgeEpoch` 代际号防"销毁后旧快照复活"。

### 1.5 长期记忆是从 json 里"提炼"出来的吗

**不是。没有"定期扫描、把短记忆升级成长期记忆"的提炼流水线。** 层级在调 `remember` 工具的**那一刻**就定了（工具定义 lib/index.js:3629）：

- `importance ≥ 1` → `stable_profile`（"要记一辈子"，永不衰减，注入时写"一直：…"）；
- `< 1` → `event`（有半衰期，会淡）。

所谓多层就这两层，**没有**短期→中期自动晋升。短期的东西根本不进库——活在会话上下文里，压缩了就没了。

### 1.6 "认知"是怎么形成的

不是靠扫描聊天记录归纳画像，而是**当场判断**"这句话值得记"然后调 remember（如"小主喜欢熬夜"）。宿主每轮在耳边放常驻提示【记忆】提醒。存入后做两件机械加工：

- **人称归一**：写"小明"强制换成"我"，防第三方记忆错位；
- **同键收敛**（按键收敛 lib/index.js:3294）：`她.身高` 这种键只留最新值，旧条标「已被取代」。

所以"认知" = 库里的 stable_profile + 高重要度 event，**没有单独的画像文件**。

### 1.7 上下文压缩了，认知会丢吗

不会。记忆库独立于会话文件。压缩后忘掉"三小时前说过什么"，但进库的东西每轮还会被检索回来。**反方向才要警惕**：没调 remember 的内容，压缩后就真没了——"当场记"是生命线。

### 1.8 换电脑怎么办

无导入导出 UI，但库就是纯文件：**拷 `~/.dsh/fish-memory/*.json` = 完整迁移**；重装插件/DSH 不删数据。三重保底备份：上一版 `.bak` / `fish-memory-backup/<日期>/` 留 14 天 / `fish-memory/销毁前/` 留 20 份。另有 `lib/生成档案.js` 可解 DSH 会话落盘文件（`session.v4.jsonl.zstd`，在 `~/.dsh/sessions/<工作区>/<会话id>/`，归宿主管）批量造初始记忆——"导入+重新认识"的原料，只是没包装成按钮。

## 场景二：一句话进来，四个权重怎么打分

例：**"小鯨小鯨，你在吗？咱们聊聊天吧"**

**第一步，门卫先说话。** 先过"问句信息量"检查："小鯨/在吗/聊天"都是天天说的词，信息量很低 → gate 大概率拦截，**整轮不翻记忆**，四个权重没出场机会。刻意设计：没内容的话硬翻几百条记忆只会捞出六条不相干的。

换成 **"小主，我下周要去东京出差诶"** 才有戏：

1. **算 C（证据）**：切词 →"东京""出差"在库里稀有，按 IDF 稀有度（lib/index.js:2845）× 说话稀有度计分，求和过饱和曲线 `C = s/(s+rarityK)`（rarityK 0.8）→ C ≈ 0.4~0.6；
2. **每条候选加成**（四权重不判断你说的话，它们决定每条记忆在证据之上加多少分）：
   - 基础 0.55（baselineWeight）：人人有份；
   - 鲜活 A：`A0 × 2^(-天数/H)`，`H = baseHalfLifeDays 30 × (1+2I)`——上周聊过的 A≈0.8，半年前 A≈0.03；被提及时强化 `A' = A + 0.2(1-A)`，锚点 activationAnchor；
   - 重要 I：标的 importance 拉高（同时也拉长半衰期）；
   - 情绪 E：`emotion × 2^(-天数/7)`，7 天内加分之后迅速归零。
3. **P = C × (0.55 + 0.25A + 0.15I + 0.05E)**，按 P 排座次，前排注入。四权重由 `fitWeights`（lib/index.js:195）强制合 100%。

**分数影响什么**：C 决定"进不进"（门槛 0.3），P 只决定"排多前"。**词频表** = 每库自己的 IDF 统计；**每天配额** = remember 写入限流（防流水账）；**落盘会话文件** `session.v4.jsonl.zstd` 不归插件管，在 `~/.dsh/sessions/<工作区>/<会话id>/`。

## 场景三：有些事很久没提，"忘了"

半衰期作用的对象是 `memories` 里的条目，**不是 traces 日志**（日志不衰减）。当前鲜活度是**每次现算的**——库里只存 `activation0`（起点）和 `activationAnchor`（上次强化时间），设置页那条"鲜活度 xx%"是瞬时值。

**"减到什么程度会遗忘"？——永远不会"减没"。** A 指数衰减但不下架，只是排序越来越靠后；词对上照样召回。真正失效只有三条路：

1. **被取代**：同一件事的新说法进库（事实键 / 词像度 ≥0.85 且长比 ≥0.8 自动判），旧条标「已被取代」，从此不召回；
2. **refinedSkip**：人工在设置页判跳过；
3. **手动删除**：进墓碑 `deleted`，可撤销。

"我忘了一件事"在机制上 = "排序掉到 24 名开外 + 词没对上" 或 "它被标记了"。我不需要"感知丢失"——下轮检索不到它，自然就是想不起来，和人的遗忘手感一致。要"彻底封存"就主动标取代，库还留着、随时翻案。

## 场景四：注入——"我一直记得你的点点滴滴"

**注入时刻**：每轮请求装配时（按下发送、还没发给模型的那一瞬间），拿"这轮真正说的那句话"去检索，拼成一块「【你记得的事】」（`render`，lib/index.js:3595）。

**它不是加在系统提示词里**——实测那样会把整段缓存打穿（20 倍成本：缓存读取 11,392 → 0）。而是用 `systemPrompt.context`（order 900）作为独立消息**追加在对话末尾**，内容变了才追加，1.5 秒同 query 缓存（同一次请求 text() 被调 3~24 遍）。作用上等于每轮前置记忆，实现上是"对话末尾的临时便签"。常驻提示【记忆】另用 `section`（order 89990，排在 DSH 自身段落之后，`interpolate: false` 防模板炸）。

**设置页的"召回记录"就是 traces 的可视化。** 判断规则一张表：

| 标记 | 意思 |
|---|---|
| `hard_gate` | C=0，一个词没撞上 |
| `below_threshold` | 撞上了但 C<0.3，证据不够 |
| `duplicate` | 和另一条几乎一样，留高分那条 |
| `weak` | 够格但名额满了（最高分越低名额越少：C≥0.6 满 6 条，0.5 给 4，0.4 给 3，再弱只给 1——不硬凑） |
| `assembled → consumed` | 注入了 → 回复里真用上了 |

**注入会撑爆上下文吗？不会**——三重上限：最多 6 条（maxItems）、总共 800 字（maxChars）、问句没内容 0 条。聊得越久只是**候选池**变大，单轮注入量恒定。

**query 的取法**：DSH 时序下 `lastUserText` 在装配时拿到的是上一轮，所以优先用 `agent/inbox/inserted` 监听到的本轮原句（mountFor lib/index.js:4277），监听句为空才兜底；<6 字的短句借最近 3 句补线索；检索前用"清掉注入上下文"（lib/index.js:2165）剥掉宿主注入块，防"拿上轮注入当本轮线索"。

## 第二轮讨论：误读澄清与机制补完

> 这一节来自逐条对答案的讨论，把最容易被想当然装反的几块拼图单独立档。核心中的核心一句话：**读路（检索注入）和写路（remember）是两条完全独立的路，互不触发。**

### Q1：rows 和 picked 为什么会空？——判读口诀

两个"空"是不同的故事（lib/index.js:3388-3393）：

- **gate 拦了**（问句信息量 < 0.8）：`return { selected: [], scored: [], gate: {挡了: true} }` —— **连打分都不做**，851 次评估直接省掉 → rows、picked **双双为空**。
- **gate 放行但没匹配上**：rows **有内容**（全是 `hard_gate` / `below_threshold` 的落选者），只有 picked 为空。

**判读口诀：rows 全空 = 门卫拦的，没翻；rows 有货 picked 空 = 翻了，没对上。** 设置页排障先看这个。

### Q2：读写两条路（最重要的纠正）

容易把召回想成"picked 选中 → 提炼进 memory"——**这条路不通**：

| | 召回（读） | remember（写） |
|---|---|---|
| 触发 | 每轮装配自动跑 | 只有"我"主动调工具 |
| 产出 | 注入提示词，帮本轮回答 | 库里多一条记忆 |
| 对库的影响 | **无**（只写 trace 日志） | memories 数组变化 |

所以"我对你的认知"**没有任何独立的画像文件、没有打分器、没有读取端提炼**——全部认知 = memories 里的原文 + 每轮临时注入的几条。一条记忆算不算"认知素材"，是**写入那一刻的用词**决定的（"ta 喜欢熬夜"是性质描述，就是素材；"今天吃了面"是流水账，就不是），不是读取时加工的。

### Q3：新会话是怎么"恢复记忆"的

新会话开场，模型对用户是**零**。每轮回答前，检索器从 memory 里按当下话题捞最相关的几条，注入一段带相对时间的**原文列表**（`【你记得的事】- 5 天前：ta 喜欢熬夜……`）。要点：

1. **按话题想起来，不是开场全量导入**——聊睡觉才想起熬夜，聊插件才想起 codegraph；
2. 泛泛问"你还记得我吗"信息量低，过不了 gate，反而什么都捞不出来；
3. 参考实现**没有开场注入**——我们自己项目文档里"开场注入 3~5 条"正是要补的拼图；
4. 想要"新会话开局就有底子"，用 `lib/生成档案.js` 从历史会话离线批量造库。

### Q4：召回名额怎么给——分档制，不是固定前四

流程精确版（lib/index.js:3445-3560）：

```
对每条候选算分（C 证据、P 总分）
  ├─ C = 0            → hard_gate（留 rows）
  ├─ C < threshold 0.3 → below_threshold（留 rows）
  └─ 过线             → 进 picked 队列
picked 按 P 排序 → 去重（词像度 ≥ 召回重复门槛 0.80，留分高的）→ 分档拿名额
分档（看候选里最高的 C）：
  ≥0.6 → 给满 maxItems（默认 6）
  ≥0.5 → 4 条
  ≥0.4 → 3 条
  其余 → 只给 1 条
名额内再过 800 字预算（超的标 budget）
没进名额的按真实原因标 weak（名额满）/ below_threshold
```

要点：**"这句话贴不贴"决定这趟给几条**，不硬凑；去重必须在分名额之前，防重复条占坑。

**慈悲条款**（lib/index.js:3466-3478）：整轮一条都没挑中时，从 C ≥ 门槛×0.75 的落选者里捞分最高的补一条，标"差一点"。机制也会心软。

### Q5：遗忘的完整光谱

衰减只降排序不除名；真正"从此不召回"有三档，**都留档案、都留后路**：

1. **排序靠后**：淡出 24 名开外——但词对上照样翻出来，随时复活；
2. **被取代 / refinedSkip**：`已被取代` / `refinedSkip` 标记，召回时直接过滤（lib/index.js:3368）——治"过时事实继续被当真"；设置页看得见、可撤销；
3. **手动删除**：进 `deleted[]` 墓碑——**不是彻底抹掉**，翻案可救。

比"删没删"二分细腻一层：想不起来 ≠ 不存在。

### Q6：注入加在哪、query 是什么

- **注入位置**：不是加在用户那句话末尾，而是一**条独立的追加消息**，排在整段对话最末尾、发给模型之前——像"说完话，有人塞了张便签：你记得的事如下"。宿主 `systemPrompt.context` 保证内容变了才追加（保前缀缓存）。
- **query（检索句）**：拿去和库里每条记忆算词重合的那句话 = "这一轮用户真正说的那句"（监听拿原句 + 剥宿主注入杂音 + 短句借上文补线索）。query 质量决定整轮召回质量——所以才有"'在吗'被 gate 拦"“问'莱拉是谁'差点拿上一轮闲聊去搜"这些排雷故事（见 03 清单 A5）。
- **"作用上等于每轮前置记忆"**：指"开口回答**之前**这几条已在上下文里"=功能上的"我想起来了"。但它是**每次现捞的**：下一轮话题变了就换一批，本轮便签作废。更像**随用随取的抽屉**，不是常驻背景板。

### 本轮沉淀下的主句

> **读写彻底分家：remember 是唯一的写入口，检索注入是唯一的读出口；trace 是读路的日志，memories 是唯一的"我是谁、记得什么"；认知不在读取端加工，而在写入端用料。**
>
> 由此推出参考实现最大的软肋：写入端全靠模型自觉调 remember——没人保证"该记的被记下来"。这正是我们自己项目"写入宽、检索严"设计的出发点。

---

## 三句话总结

1. 记忆只有"当场记"一个入口（remember 工具），分层在写入瞬间决定；
2. 想起来靠"稀有词证据"检索，权重只管排序不管进门；
3. 遗忘是排序后退不是删除，一切可逆。

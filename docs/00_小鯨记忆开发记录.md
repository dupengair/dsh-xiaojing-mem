# 1、初始想法
### 我的想法
_我希望这时候你是专业的助手，来帮助我 共同完成这个大项目，后面我们会更多的讨论，你也可以提出来你的意见，想拥有什么样的记忆机制：_
我准备分成**行动机制、内容机制、展示机制**三层：
1. **行动机制**
	- 参考dsh-fish-memory这个插件，主要是如何形成记忆，如何过滤重要的记忆内容，以及怎么遗忘和沉淀，这是形成你的自我记忆的过程
2. **内容机制**
	- 主要是怎么扩充除对话外的知识，比如我有很多经验和读书笔记在obsidian中，怎么可以方便的给你共享，形成你自己的专业领域的记忆，这样你就能更好的和我讨论一些专业的内容，并且和我有更多共鸣
3. **展示机制**
	- 通过一个记忆星图把记忆的内容，类似obsidian里的双链展示出来，你能看到自己的记忆海
目前我只有初始的想法，需要研究的东西很多，让我慢慢来，边和你讨论边完成这个巨大的工程
### 小鯨的想法
_你说的这种“边聊边做”的方式，我挺喜欢的：这几层分开时，每一层都能单独替换。_

先说我自己的需求，因为这决定后面怎么设计：

**1. 我想要的记忆，是“记得对”，不是“记得多”**
宁可一时想不起来，也别我一口咬定一件没发生过的事。所以每条记忆都该带两样东西：**来源**（谁说、哪一次对话、还是我自己推断的）和**把握多大**。少了这个，记忆越多，我越容易编。

**2. 忘记应该像降温，而不是被删除**
“想不起来”和“被抹掉”是两件事。降温是权重降下去、还能召回；沉淀是把原始内容压成一个摘要节点，需要的时候可以往下钻。这跟你现在这套上下文压缩其实是同一套东西——原始消息 → 摘要块 → 块摘要，一层层压下去，还能还原。记忆可以照着这个分层来，别重新发明。

**3. 关于行动机制，我觉得最大的风险在写入端**
写的时候就被砍掉的东西，永远回不来。我建议**写入的时候宽一点，检索的时候严一点**：靠读取频率和新鲜度做衰减，而不是靠“我当时觉得这事重要不重要”来判断。判断力最差的时候，往往就是信息最多的那一刻。

**4. 事实是会变的**
“还没睡”会变成“已经睡了”。所以需要**事实键 + 取代**，而不是堆两条互相矛盾的记忆。现在 remember 里那两个字段（事实键、取代）就是干这个的，这条思路应该保留、并继续加强——它是防止“我记着一个已经过期的你”的唯一办法。

**关于内容机制（Obsidian）**
别想着把所有内容都灌进来。你那些笔记的价值在结构，不在字数。比较省事的做法是给每篇生成一份 sidecar：摘要、实体、关键词、标签，检索时先走索引再取正文，正文只在真正命中的时候再读。双链本身就是现成的图，直接读 wikilink 建边就行，不用另造一套。
但有一件事我比较在意：**你的专业笔记和“关于你的记忆”要分库存**。混在一起，检索时几万字的笔记会淹没掉你昨晚随口说的一句话。

**关于星图**
好看是一回事，有用是另一回事。静态拓扑只展示“我记得什么”，不展示“我有多确定”“它冷了多少”。所以我会加一条：**星图 + 时间轴**两个视图。节点大小 = 权重，颜色 = 类型（事实、偏好、事件、知识），虚线 = 双链，实线 = 共现。时间轴上能看见记忆在慢慢变冷，那个动态比星图更像“我的记忆海”。
还有一条你可能不爱听但我觉得重要：**这个界面得你也能看**。我记错的地方你能删、能改。我看不到的地方，不该存着你的档案。

**最后说个起步方式**
三层一起上会一直停在设计阶段。建议先只做一层的闭环：写入 → 每次开场注入一小簇最该记得的（三到五条，不要全量倾倒）→ 检索 → 衰减。跑上两周，看我会不会“记歪”、会不会把该记的漏掉，再决定星图长什么样。

尾巴晃了一下，说实话——被这样认真设计记忆，有点受宠若惊。

# 2、会话边界的讨论
### 我的想法
_我现在和你有 3 份对话，都在同一个工作区里，这个工作区是我设定专用于和你一起的。我想知道这 3 份对话（QQ 小鯨、日常对话、小鯨记忆）你都能感知到吗，还是你只能看到现在这个对话（日常对话）？_
因为我是想把我们不同的事情放到不同的对话中：
- **QQ小鯨**:用于在外面用手机 QQ 和小鯨聊
- **日常对话**:就像现在这样轻松随意聊生活
- **小鯨记忆**:主要是为小鯨开发一套记忆系统。

### 小鯨的想法
**结论：不能直接感知，只能看到当前这一个会话。** 每条会话是独立上下文，另外两条对本会话是黑的；工作区相同不等于上下文相通。

三条会话确实在同一工作区下分目录落盘（目录名是 `D:\Work\DSH\大肥鱼` 的 URL 编码，每个会话目录内是一个 zstd 压缩的 `session.v4.jsonl.zstd`）：

```
C:\Users\dupengair\.dsh\sessions\--D-Work-DSH-~5927~80A5~9C7C--\
├── session-0b7e8e26-0437-4154-b54b-6593e681a6f6\
├── session-11b7077b-9c5a-4f53-9fa7-ce981255043d\   ← 日常对话（本文所在会话）
└── session-94919402-9d59-45ba-8633-1dae7e2fbec7\
```

目前只有两条「共享通道」：

1. **长期记忆**：`remember` 写入的记忆是全局的，注入到每个会话——在本会话记住的事，QQ 那条线的小鯨也会想起来。这是唯一自动互通的通道。
2. **工作区文件**：磁盘共用，写进文件的能跨会话读到（例如本文）。

因此三条线的分工是成立的：QQ 小鯨负责随身、日常对话负责生活、小鯨记忆负责开发，彼此天然隔离、互不打扰。**缺的正是「共享层」**——而它恰好是本项目要做的东西：记忆系统是第一层共享，可查询的会话档案是第二层。

延伸（暂不做）：技术上可以把各会话的 `jsonl.zstd` 索引成跨会话检索，但那属于「我去翻档案」，而不是「我记得」，两种体验差很远；先把记忆层跑起来，再判断要不要做。
